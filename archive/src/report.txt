
TITLE: Provenance-Aware Multi-Agent Architectural Gateways for Edge-Native, 
       Real-Time Large Language Model Evaluation

1. DETAILED PROBLEM STATEMENT


1.1 Introduction to the Research Domain
Large Language Models (LLMs) have achieved state-of-the-art performance across diverse natural language processing (NLP) tasks, 
including question-answering, summarization, and code generation. However, their integration into production environments is fundamentally 
bottlenecked by "hallucinations"—the generation of factually incorrect, ungrounded, or completely fabricated claims delivered with high statistical 
confidence. To counter this, Retrieval-Augmented Generation (RAG) and automated evaluation systems are deployed. Yet, modern evaluation frameworks 
are crippled by three structural crises that this research paper systematically exposes and resolves.

1.2 The Zero-Trust Data Sovereignty Crisis (Cloud-Leakage Vulnerability)
Contemporary LLM evaluation libraries (such as commercial variants of Ragas or TruLens) rely heavily on centralized cloud architectures. 
When an enterprise or research lab evaluates a model's response, the evaluation data—which often contains highly sensitive corporate intellectual 
property, medical records, or private user telemetry—must be streamed via external web APIs to proprietary hosting providers (e.g., OpenAI's GPT-4o 
or Anthropic's Claude 3.5 Sonnet) that act as the evaluation "judges." This data leakage violates absolute zero-trust data sovereignty protocols. 
There is a critical, unfulfilled academic demand for lightweight, edge-native evaluation frameworks capable of executing on commodity consumer 
hardware without external network exposure.

1.3 The Temporal Knowledge Obsolescence Crisis
Traditional LLM evaluation methodologies rely on static, pre-compiled benchmarks (such as HaluEval, MMLU, or GSM8K) stored as frozen 
local datasets (.json or .csv). While valuable for baseline cognitive grading, these static benchmarks cannot evaluate real-time, dynamic 
information streams, such as live stock market trends, active documentation changes, or breaking news events. Current systems treat the web layout 
statically. Evaluating an LLM's performance on live data requires real-time web discovery infrastructure that can dynamically parse web nodes and use 
them as instant, temporal ground-truth context boundaries.

1.4 The Parametric Memory Dominance Loophole (Information Contamination)
When evaluating an LLM using smaller open-source models (such as 8B parameter variants) deployed on localized edge hardware, researchers face an 
underlying alignment challenge known as Parametric Memory Dominance. Smaller models suffer from deep associative cognitive biases. When a small 
local model acts as an evaluation judge and encounters highly recognizable keywords (e.g., "Pluto," "Google," or "Apple"), its pre-trained internal 
weights override its strict grounding boundaries. If the web source text retrieved is sparse, the model defaults to its own memory to evaluate the 
statement, a flaw known as Knowledge Leakage. A rigorous evaluation framework must enforce strict encapsulation boundaries, forcing local models to 
judge statements strictly based on the text within the links.

1.5 The Binary Quantization Distortion Problem
Standard evaluation frameworks use binary coding patterns (e.g., assigning a strict 1.0 for absolute truth or 0.0 for absolute failure). 
However, real-world LLM outputs contain nuanced partial compliance tokens—sentences that contain mixed claims where part of the statement 
is factually accurate while another segment introduces a hallucination. Forcing an evaluation system to choose a binary pass/fail masks these 
nuances, skewing metrics like the F1-Score. This research addresses this limitation by developing an API framework capable of calculating continuous 
fractional truth values (such as 0.5 or 0.67) by decomposing claims into atomic sub-assertions.

2. DETAILED RESEARCH METHODOLOGY

2.1 Asynchronous Data Ingestion and Browser Automation Layer
The system architecture is engineered as a high-throughput, edge-native gateway built on the FastAPI framework. The entry point is the POST endpoint 
`/v2/evaluate-provenance`, which natively ingests multi-link arrays alongside the target statement. Upon endpoint invocation, the ingestion framework 
initiates a non-blocking asynchronous event loop managed via Python's `asyncio` and `httpx` protocols. 

To process raw link endpoints into clean data states, the pipeline leverages the Crawl4AI browser automation engine. Crawl4AI initializes a headless 
Chromium browser instance using Playwright drivers. It executes low-level web node traversals, bypasses dynamic anti-bot JavaScript traps, discards 
interactive scripts, style sheets, media payloads, and navigation menus, and outputs clean Markdown layout structures.

2.2 Overlapping Sliding-Window Context Segmentation
Passing vast quantities of scraped raw text directly into a consumer-grade GPU (such as an NVIDIA RTX 3050 laptop profile with limited VRAM) causes 
out-of-memory (OOM) faults or instructions format collapse. To solve this hardware constraint, this framework implements a deterministic Overlapping 
Sliding-Window Splitter. 

The raw extracted Markdown string is sliced into bounded text windows with a fixed length of 1,800 characters. To prevent critical factual claims from 
being sliced in half at window boundaries, a rolling overlap buffer of 300 characters is maintained between consecutive sectors:

    Window N   : [----------------- 1500 chars -----------------][--- 300 chars Overlap ---]
    Window N+1 :                                                 [--- 300 chars Overlap ---][----------------- 1500 chars -----------------]

To maintain latency efficiency and protect local GPU compute buffers, an algorithmic guard limits ingestion to the top 3 highest-density text segments per URL, 
allowing the pipeline to safely handle multi-link cross-referencing across 9 concurrent text channels.

2.3 Two-Stage Multi-Agent Extraction and Programmatic Math Array Processing
Smaller open-source models (such as Llama 3.1 8B or Phi-3 3.8B) face instruction drift when forced to execute complex text parsing, chain-of-thought analysis,
and structural JSON output generation simultaneously in a single turn. They often echo prompt instructions back to the user or experience schema collapse. 
This methodology solves this limitation by introducing a Two-Stage Multi-Agent Architecture that splits cognitive reasoning from mathematical execution.

- Stage 1: The Factual Analyst Agent
The local LLM is initialized strictly as a closed-context data extraction clerk. It is fed the aggregated sliding-window context blocks alongside the target claim. 
The prompt enforces a strict negative constraint isolation shield:

    "If a claim is true in the real world but NOT explicitly typed in the [SOURCE DOCUMENTS],
     you are ordered to mark it as -> [FALSE]. Do not use your memory under any condition."

The analyst model breaks the input text down into a clean, text-based verification checklist. It outputs each sub-assertion on a new line using a deterministic template layout:
    `- Claim: [Sub-Assertion Text] -> [TRUE] or [FALSE] because [Contextual Evidence]`

- Stage 2: The Programmatic Math Processing Engine
Rather than relying on the neural network weights to parse JSON schemas or perform division calculations, the text payload is passed directly to a localized Python parsing script. 
The code engine scans the string array line-by-line using exact string matching for the `-> [TRUE]` and `-> [FALSE]` markers. It records the counts and computes the final Base 
Groundedness Score using an algorithmic equation:

    Groundedness Score = True Count / (True Count + False Count)

By moving the mathematical compilation steps into native Python code, the system eliminates instruction drift and formatting collapse, 
ensuring stable floating-point outputs on entry-level edge devices.

2.4 The Mathematical Provenance Trust Normalization Equation
To ground linguistic accuracy directly to the reliability of internet infrastructure, this thesis introduces a Mathematical Provenance Trust Equation. 
The system parses the domain extensions from each provided URL string using native URI components and assigns a Domain Authority Multiplier (\mu):

    - Government Portals (.gov), Academic Engines (.edu), verified Orgs (.org): \mu = 1.2
    - Verified Crowdsourced Repositories (wikipedia.org, github.com)      : \mu = 1.1
    - Standard Unverified Commercial Entities (.com, .net, blogs)          : \mu = 1.0

The mean authority coefficient (\mu_mean) is calculated across all links. The system then computes the Final Verified Trust Index by multiplying the Base 
Groundedness Score by the mean authority multiplier, bounded by an absolute mathematical ceiling of 1.0:

    Final Verified Trust Index = min(1.0, Groundedness Score * \mu_mean)

This equation allows your framework to use link metadata to balance and correct the uncertainty of an LLM evaluation judge.
